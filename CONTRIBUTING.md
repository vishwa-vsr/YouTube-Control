# Contributing to YouTube Control

Thank you for contributing to YouTube Control! This guide explains how to set up the project locally, modify code safely, and submit pull requests.

---

## Code of Conduct

We follow standard open-source community standards:
* **Be respectful and constructive** in discussions and code reviews.
* **Focus on clear solutions** and report reproducible issues.
* Harassment, spam, or hostile behavior will not be tolerated.

---

## Workflow Overview

1. All development happens on the `src/` folder.
2. Never manually edit files inside `dist/` or `releases/` (these are generated by `build.py`).
3. Run `python build.py -y` before testing your changes in your browser.

---

## Development Setup

### 1. Prerequisites
* [Git](https://git-scm.com/)
* [Python 3.8+](https://www.python.org/downloads/)

### 2. Fork and Clone
```bash
git clone https://github.com/YOUR-USERNAME/YouTube-Control.git
cd YouTube-Control
```

### 3. Create a Branch
```bash
git checkout -b feature/your-feature-name
# or for bug fixes:
git checkout -b fix/issue-description
```

### 4. Source Files Guide

| File | Role |
| :--- | :--- |
| `src/manifest.json` | Extension manifest (permissions, content scripts, versions). |
| `src/background.js` | Service worker for uninstall feedback survey and install date tracking. |
| `src/content.js` | Injected JavaScript controlling YouTube DOM adjustments and button handlers. |
| `src/content.css` | Injected CSS hiding YouTube clutter and adjusting layouts. |
| `src/popup.html` | Extension settings menu markup. |
| `src/popup.css` | Extension settings menu styling. |
| `src/popup.js` | Extension settings controller and storage handler. |
| `src/icons/` | Extension icon assets in 16px, 48px, and 128px formats. |

### 5. Build Locally
Compile the `src/` folder into browser-ready distributions:

```bash
python build.py -y
```

Load the unpacked extension folder (`dist/chrome`, `dist/firefox`, or `dist/edge`) into your browser.

## Code Style & Architecture Guidelines

### CSS (`src/content.css`)
* **Follow section comments**: Keep styles organized in their respective numbered sections (e.g., `/* 14. WEB FULLSCREEN */`).
* **Use extension prefixes**: Prefix extension-injected classes with `.yt-` (e.g., `.yt-web-fullscreen-active`, `.yt-hide-feed`).
* **Keep selectors specific**: Avoid generic tag selectors that could unintentionally break YouTube's native styles.
* **Avoid unnecessary `!important`**: Only use `!important` when overriding YouTube's inline styles.

### JavaScript (`src/content.js` and `src/popup.js`)
* **Use `cachedSettings`**: Read preferences from the local `cachedSettings` object rather than repeatedly calling asynchronous storage in high-frequency events.
* **Dispatch layout events**: Use `dispatchResize()` when modifying player dimensions so YouTube's video player recalculates its aspect ratio properly.
* **Capture phase listeners**: Use `document.addEventListener('keydown', handler, true)` when intercepting shortcuts before YouTube's native player captures them.
* **Indentation**: Use 2 spaces consistently.

## Testing Checklist

Before submitting your pull request, verify that:

- [ ] **Build succeeds**: `python build.py -y` runs without errors.
- [ ] **Default Layout**: Video pages work normally in standard view.
- [ ] **Cinema / Theater Mode**: Pressing `T` switches modes cleanly without layout breakages.
- [ ] **Mini Fullscreen**: Entering and exiting Mini Fullscreen (via button, `Esc`, and `T`) functions as expected.
- [ ] **Toggle Settings**: Toggling your feature ON and OFF in the popup applies and reverts changes immediately without needing a page refresh.
- [ ] **DevTools Console**: No new JavaScript errors or unhandled exceptions appear in the browser console (`F12`).

---

## Submitting a Pull Request

1. Commit your changes with a clear message:
   ```bash
   git add src/
   git commit -m "Fix: resolve theater mode comment clipping"
   git push origin feature/your-feature-name
   ```
2. Open a Pull Request against the `master` branch on GitHub.
3. Link the PR to any related issue (e.g., `Fixes #12`).
4. Include screenshots or a short GIF if you made visual changes.
